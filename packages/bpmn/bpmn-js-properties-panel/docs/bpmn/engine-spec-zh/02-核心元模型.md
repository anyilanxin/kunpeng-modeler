# 第 2 章 核心元模型

> 对应原规范：Ch 8 BPMN Core Structure（p.77-134），重点是 8.3 Foundation 与 8.4 Common Elements

## 2.1 总览

BPMN 元模型按"包"组织，依赖关系如下：

```
Infrastructure (Definitions, Import)
    ↓
Foundation (BaseElement, Documentation, Extensibility, RootElement)
    ↓
Common (FlowElement, FlowElementsContainer, SequenceFlow, FlowNode, Gateway,
        Event, Expression, ItemDefinition, Message, Error, Escalation,
        Correlation, Resource, Artifact)
    ↓
Services (Interface, Operation, EndPoint)
    ↓
Process / Collaboration / Choreography
```

**引擎开发者要重点掌握**：

- Foundation 包：所有元素的根基
- Common 包：流程执行的最小构建块

## 2.2 Infrastructure 包

### 2.2.1 Definitions（根容器） ✅

> 对应原书 §8.2.1（p.79）

`Definitions` 是 BPMN XML 文档的**根元素**，包含模型中所有可被复用的 RootElement。

| 属性               | 类型   | 说明                                       |
| ------------------ | ------ | ------------------------------------------ |
| id                 | string | 唯一标识                                   |
| name               | string | 模型名称                                   |
| targetNamespace    | anyURI | **目标命名空间**（重要，相当于"流程分类"） |
| typeLanguage       | anyURI | 类型定义语言，默认 XML Schema              |
| expressionLanguage | anyURI | 表达式语言，默认 XPath                     |
| exporter           | string | 导出工具标识                               |
| exporterVersion    | string | 导出工具版本                               |

### 2.2.2 Import（外部导入） ✅

> 对应原书 §8.2.2（p.81）

`Import` 用于引入外部类型定义、WSDL、XSD 等。

| 属性 | 类型 | 说明 |
| --- | --- | --- |
| namespace | anyURI | **必需**。被导入资源的命名空间 |
| location | string | **必需**。被导入资源的物理位置 |
| importType | anyURI | **必需**。导入类型（如 `http://schemas.xmlsoap.org/wsdl/` 表示 WSDL） |

## 2.3 Foundation 包（根基元素）

### 2.3.1 BaseElement ✅

> 对应原书 §8.3.1（p.84）

`BaseElement` 是**几乎所有 BPMN 元素的抽象基类**。引擎内部建模时，所有元素类型都应继承自此。

**核心属性**：

| 属性 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| **id** | string | ⚠️ 条件必需 | 唯一标识。**若被其他元素引用则必需**；否则可选 |
| documentation | Documentation [0..*] | 否 | 元素的文字描述（可多条） |
| extensionDefinitions | ExtensionDefinition [0..*] | 否 | 扩展属性定义（XSD 间交互时不适用） |
| extensionValues | ExtensionAttributeValue [0..*] | 否 | 扩展属性值（XSD 间交互时不适用） |

> ⚠️ **id 规则**：BPMN 的 id 在 XML 中是 `xsd:ID` 类型，必须满足 NCName 规范（不能以数字开头、不能含空格等）。

**XSD 形式**：

```xml
<xsd:complexType name="tBaseElement" abstract="true">
  <xsd:sequence>
    <xsd:element ref="documentation" minOccurs="0" maxOccurs="unbounded"/>
    <xsd:element ref="extensionElements" minOccurs="0" maxOccurs="1"/>
  </xsd:sequence>
  <xsd:attribute name="id" type="xsd:ID" use="optional"/>
  <xsd:anyAttribute namespace="##other" processContents="lax"/>
</xsd:complexType>
```

### 2.3.2 Documentation ✅

> 对应原书 §8.3.2（p.84）

每个 BaseElement 都可以挂载多条 Documentation。

| 属性 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| text | string | — | 文档内容（**放在 XML 元素的 body 中**，不是属性） |
| textFormat | string | `text/plain` | 文本格式，必须是 MIME 类型 |

**XML 示例**：

```xml
<documentation>An example of how the documentation text is entered.</documentation>
```

### 2.3.3 Extensibility（扩展机制） ✅

> 对应原书 §8.3.3（p.85）

BPMN 元模型设计上**允许扩展**，扩展不影响标准元素的兼容性。

**扩展由四个元素构成**：

| 元素 | 作用 |
| --- | --- |
| `Extension` | 将 ExtensionDefinition 绑定到具体 BPMN 模型定义 |
| `ExtensionDefinition` | 定义一组扩展属性（XSD 中由外部 schema 提供） |
| `ExtensionAttributeDefinition` | 单个扩展属性的定义（name、type、isReference） |
| `ExtensionAttributeValue` | 扩展属性的实际值 |

**Extension 元素属性**：

| 属性 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| mustUnderstand | boolean | false | **若为 true，处理方必须理解扩展语义才能正确处理模型** |
| definition | ExtensionDefinition | — | 指向扩展定义（XSD 中用 QName 引用） |

ℹ️ **实践要点**：

- 在 XML 交换场景下，扩展走 XSD 的 `anyAttribute` / `any` 机制，不需要显式用上述四个元素
- 引擎解析扩展时，应**保留未知扩展**（不要丢弃），便于后续工具消费
- `mustUnderstand=true` 的扩展若引擎不支持，**应拒绝执行**而非忽略

### 2.3.4 RootElement ✅

> 对应原书 §8.3.5（p.92）

`RootElement` 是所有"可被 Definitions 直接包含的顶级元素"的抽象基类。

**特点**：

- 拥有**独立的生命周期**，删除其他元素不会删除它
- 可被多个其他元素**引用**（复用）
- 典型子类：`Collaboration`、`Process`、`Choreography`、`Message`、`Error`、`Escalation`、`ItemDefinition`、`Interface` 等

ℹ️ **引擎实现提示**：RootElement 通常作为流程定义仓库中的顶级资源存储，可被多个流程通过 ID 引用。

### 2.3.5 External Relationship（外部关系） ℹ️

> 对应原书 §8.3.4（p.89）

`Relationship` 元素用于建立 BPMN 元素与外部模型（如 UML、Visio）的关联，主要用于追溯、衍生等场景。

| 属性      | 类型                       | 说明                              |
| --------- | -------------------------- | --------------------------------- |
| type      | string                     | 关系类型描述（如 "reengineered"） |
| direction | None/Forward/Backward/Both | 关系方向                          |
| sources   | Element [1..*]             | 源元素                            |
| targets   | Element [1..*]             | 目标元素                          |

引擎**通常不需要执行**这类关系，主要用于建模工具。

## 2.4 Common 包（公共元素）

### 2.4.1 FlowElement ✅

> 对应原书 §8.4.7（p.114）

`FlowElement` 是流程图里**所有可见元素**（节点 + 连线）的抽象基类，继承自 BaseElement。

| 属性 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| id | string | ✅ | 在 FlowElementsContainer 范围内唯一 |
| name | string | 否 | 元素名称（建议必填，便于人读） |
| auditing | Auditing | 否 | 审计信息（很少用） |
| monitoring | Monitoring | 否 | 监控信息（很少用） |
| categoryValueRef | CategoryValue [0..*] | 否 | **业务分类标签**（对应规范中的 category 机制） |

**直接子类**：

- `SequenceFlow`（连线）
- `FlowNode`（节点，进一步派生出 Activity / Event / Gateway）
- `DataObject`（数据对象）
- `DataObjectReference`

### 2.4.2 FlowElementsContainer ✅

> 对应原书 §8.4.8（p.116）

`FlowElementsContainer` 是**可以装 FlowElement 的容器**的抽象基类。

| 属性         | 类型               | 说明                     |
| ------------ | ------------------ | ------------------------ |
| flowElements | FlowElement [0..*] | 容器内的所有 FlowElement |

**具体实现类**：

- `Process`（流程）
- `SubProcess`（子流程）

ℹ️ **引擎实现提示**：FlowElementsContainer 的 flowElements 是一个**有序集合**，但执行顺序由 SequenceFlow 决定，而不是声明顺序。

### 2.4.3 FlowNode ✅

> 对应原书 §8.4.13.1（p.127）

`FlowNode` 是**所有可被 SequenceFlow 连接的节点**的抽象基类。

| 属性     | 类型                | 说明                 |
| -------- | ------------------- | -------------------- |
| incoming | SequenceFlow [0..*] | 进入此节点的所有连线 |
| outgoing | SequenceFlow [0..*] | 离开此节点的所有连线 |

**核心派生关系**：

```
FlowNode
├── Activity（活动）
│   ├── Task → ServiceTask, UserTask, SendTask, ReceiveTask, ...
│   ├── SubProcess → AdHocSubProcess, Transaction, EventSubProcess
│   └── CallActivity
├── Gateway（网关）
│   ├── ExclusiveGateway
│   ├── InclusiveGateway
│   ├── ParallelGateway
│   ├── ComplexGateway
│   └── EventBasedGateway
├── Event（事件）
│   ├── StartEvent
│   ├── EndEvent
│   ├── IntermediateCatchEvent
│   ├── IntermediateThrowEvent
│   └── BoundaryEvent
└── ChoreographyActivity（编排活动，引擎一般不实现）
```

**关键查询方法**（引擎应提供）：

- `getIncoming()` - 所有入向连线
- `getOutgoing()` - 所有出向连线
- `getPreviousNodes()` - 前驱节点（跨连线）
- `getSucceedingNodes()` - 后继节点（跨连线）

### 2.4.4 SequenceFlow ✅

> 对应原书 §8.4.13（p.125）

`SequenceFlow` 是**节点之间的顺序连线**，表示流程执行路径。

| 属性 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| id | string | ✅ | 唯一标识 |
| name | string | 否 | 连线名称 |
| **sourceRef** | FlowNode | ✅ | **源节点** |
| **targetRef** | FlowNode | ✅ | **目标节点** |
| conditionExpression | Expression | ⚠️ 条件 | **条件表达式**（仅 XOR/Inclusive Gateway 出向连线可有） |
| isImmediate | boolean | 否 | 是否立即转移（默认 false） |
| messageRef | Message | 否 | （不常用） |

✅ **规范性约束**：

- SequenceFlow 的两端必须都是 FlowNode
- **条件表达式只允许出现在 Gateway 的出向连线上**
- 普通节点的出向连线**不允许**有条件
- Default 流（默认流）通过源 Gateway 的 `default` 属性指定，不在 SequenceFlow 上

### 2.4.5 Expression ✅

> 对应原书 §8.4.6（p.112）

BPMN 表达式的基类。

**核心子类**：

#### FormalExpression

| 属性 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| language | anyURI | 取自 Definitions.expressionLanguage | 表达式语言（XPath、UEL、Groovy 等） |
| evaluatesToTypeRef | ItemDefinition | — | 表达式求值结果类型 |
| body | string（XML body） | — | 表达式正文 |

✅ **Common Executable 子类强制使用 XPath** 作为表达式语言。

### 2.4.6 Gateway（网关基类） ✅

> 对应原书 §8.4.9（p.118）

`Gateway` 是所有网关的抽象基类，继承自 FlowNode。

| 属性 | 类型 | 说明 |
| --- | --- | --- |
| gatewayDirection | GatewayDirection | **网关方向**：Unspecified / Mixed / Converging（汇聚）/ Diverging（分叉） |
| default | SequenceFlow | 默认出向流（仅 Exclusive/Inclusive 可用） |

**五种具体网关**：

| 网关              | 中文            | 行为                   | 详见         |
| ----------------- | --------------- | ---------------------- | ------------ |
| ExclusiveGateway  | 排他网关（XOR） | 按条件选一条路径       | `08-网关.md` |
| InclusiveGateway  | 包容网关（OR）  | 满足条件的所有路径都走 | `08-网关.md` |
| ParallelGateway   | 并行网关（AND） | 全部分叉/全部汇聚      | `08-网关.md` |
| ComplexGateway    | 复杂网关        | 自定义条件             | `08-网关.md` |
| EventBasedGateway | 基于事件的网关  | 等待事件决定路径       | `08-网关.md` |

## 2.5 引擎实现要点

### 2.5.1 类型系统设计

引擎内部建议建立以下类型层次（以 Java 为例）：

```java
interface BaseElement {
    String getId();
    List<Documentation> getDocumentation();
    ExtensionElements getExtensionElements();
}

interface FlowElement extends BaseElement {
    String getName();
    List<CategoryValue> getCategoryValueRef();
}

interface FlowNode extends FlowElement {
    Collection<SequenceFlow> getIncoming();
    Collection<SequenceFlow> getOutgoing();
}

interface SequenceFlow extends FlowElement {
    FlowNode getSource();
    FlowNode getTarget();
    Expression getConditionExpression();
}

interface FlowElementsContainer extends BaseElement {
    Collection<FlowElement> getFlowElements();
}
```

### 2.5.2 解析器扩展点

✅ 引擎解析器**必须**支持：

- 标准 BPMN 元素的 XML namespace：`http://www.omg.org/spec/BPMN/20100524/MODEL`
- 通过 `extensionElements` 接受任意扩展属性
- 通过 `anyAttribute` 接受任意扩展属性

✅ 引擎**应当**支持：

- 自定义 namespace 的子元素（如 `camunda:xxx`、`flowable:xxx`）
- 在未知元素上保留原始数据，便于回写

### 2.5.3 ID 解析策略

BPMN 的 ID 引用有两种方式：

1. **同文档引用**：直接用 id 引用，如 `<sequenceFlow sourceRef="task1" .../>`
2. **跨文档引用**：用 QName（namespace + id），如 `<messageRef>ns1:msg1</messageRef>`

引擎解析时应建立**ID 索引表**，便于在解析完成后做引用解析。

### 2.5.4 命名空间管理

| 命名空间 | 含义 |
| --- | --- |
| `http://www.omg.org/spec/BPMN/20100524/MODEL` | BPMN 标准元素 |
| `http://www.omg.org/spec/BPMN/20100524/DI` | Diagram Interchange（绘图交换，引擎一般不用） |
| `http://www.omg.org/spec/DD/20100524/DI` | DI 基础 |
| `http://www.omg.org/spec/DD/20100524/DC` | DC 基础 |
| 厂商扩展 | 如 camunda、flowable 等 |
