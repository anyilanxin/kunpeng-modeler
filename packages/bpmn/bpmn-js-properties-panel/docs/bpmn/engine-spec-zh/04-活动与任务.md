# 第 4 章 活动与任务

> 对应原规范：Ch 10.3 Activities（p.179-231）

## 4.1 Activity 抽象基类

> 对应原书 §10.3（p.179）

`Activity` 是流程中**所有可执行工作**的抽象基类，继承自 FlowNode。

### 4.1.1 核心属性

| 属性 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| **isForCompensation** | boolean | false | **是否为补偿活动**。true 表示只在补偿事件触发时执行 |
| loopCharacteristics | LoopCharacteristics [0..1] | — | 循环特性（标准循环或多实例） |
| resources | ResourceRole [0..*] | — | 执行此活动的资源（人/系统） |
| default | SequenceFlow [0..1] | — | 默认出向流（当其他条件都不满足时走这条） |
| ioSpecification | InputOutputSpecification [0..1] | — | 输入输出规格 |
| properties | Property [0..*] | — | 自定义属性 |
| **boundaryEventRefs** | BoundaryEvent [0..*] | — | **挂在边界的事件**（错误、定时器、消息等） |
| dataInputAssociations | DataInputAssociation [0..*] | — | 输入数据绑定 |
| dataOutputAssociations | DataOutputAssociation [0..*] | — | 输出数据绑定 |
| startQuantity | integer | 1 | **触发所需 token 数**（一般不用） |
| completionQuantity | integer | 1 | 完成时产出的 token 数 |

### 4.1.2 实例运行时属性（表达式可访问）

| 属性  | 说明                                  |
| ----- | ------------------------------------- |
| state | 当前活动状态（参见 §13.3.2 生命周期） |

### 4.1.3 Sequence Flow 连接规则 ✅

✅ **规范性要求**：

- Activity 可以有**多条入向 SequenceFlow**，但被视作**非受控流**（uncontrolled flow）—— 任一 token 到达即触发，**不等待其他路径**
- Activity 可以有**多条出向 SequenceFlow**，每条都会产生一个并行 token
- 无入向 SequenceFlow 的 Activity 必须在流程启动时被实例化（除 Compensation Activity 和 Event Sub-Process）
- 无出向 SequenceFlow 的 Activity 标记流程路径的结束

⚠️ **关键差异**：多入向连线 ≠ Gateway 汇聚！要等待 token 全部到达，必须用 ParallelGateway。

### 4.1.4 Activity 的派生类

```
Activity
├── Task（原子任务）
│   ├── Abstract Task (无类型 Task)
│   ├── ServiceTask
│   ├── SendTask
│   ├── ReceiveTask
│   ├── UserTask
│   ├── ManualTask
│   ├── BusinessRuleTask
│   └── ScriptTask
├── SubProcess（复合活动）
│   ├── EmbeddedSubProcess（普通嵌入子流程）
│   ├── EventSubProcess（事件子流程）
│   ├── Transaction（事务子流程）
│   └── AdHocSubProcess（Ad-Hoc 子流程）
└── CallActivity（调用活动）
```

## 4.2 Task 类型详解

> 对应原书 §10.3.3（p.186-192）

### 4.2.1 Service Task（服务任务） ✅

**用途**：调用某种服务（Web Service、自动化应用）。

| 属性 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| **implementation** | string | `##webService` | 实现技术（`##WebService`、`##unspecified` 或自定义 URI） |
| **operationRef** | Operation [0..1] | — | 调用的 Operation |

✅ **数据约束**：

- 恰好一个 inputSet、最多一个 outputSet
- 单个 DataInput，结构与 Operation.inMessageRef 指向的 Message 一致
- 若 Operation 有输出 Message，则 Service Task 有单个 DataOutput 与之对应

### 4.2.2 Send Task（发送任务） ✅

**用途**：向外部 Participant 发送 Message，发送完毕即完成。

| 属性           | 类型           | 默认           | 说明             |
| -------------- | -------------- | -------------- | ---------------- |
| messageRef     | Message [0..1] | —              | 要发送的消息     |
| operationRef   | Operation      | —              | 调用的 Operation |
| implementation | string         | `##webService` | 实现技术         |

✅ **数据流**：执行时 DataInput 的数据**自动转入** Message 载荷。

### 4.2.3 Receive Task（接收任务） ✅

**用途**：等待外部 Participant 发来的 Message，接收完毕即完成。

| 属性 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| messageRef | Message [0..1] | — | 要接收的消息 |
| **instantiate** | boolean | false | **是否作为流程启动入口**（true 时不能有入向 SequenceFlow） |
| operationRef | Operation | — | 接收消息的 Operation |
| implementation | string | `##webService` | 实现技术 |

✅ **关键能力**：`instantiate=true` 的 Receive Task 可以**启动一个新的流程实例**（等同于 Message Start Event）。

### 4.2.4 User Task（用户任务） ✅

**用途**：人工通过软件应用完成的任务，由 task manager 调度。

| 属性 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| implementation | string | `##unspecified` | 实现技术（可设为 WS-HumanTask 等） |
| renderings | Rendering [0..*] | — | UI 渲染扩展点 |

**运行时实例属性**：

| 属性         | 说明                                    |
| ------------ | --------------------------------------- |
| actualOwner  | **认领并实际负责任务的用户**（user id） |
| taskPriority | 任务优先级                              |

**关键 Human Performer 角色**：

- `Performer`（执行者）- 通用角色
- `HumanPerformer`（人工执行者）- 特化 Performer
- `PotentialOwner`（潜在所有者）- 可以 claim 任务的人

### 4.2.5 Manual Task（手工任务） ℹ️

**用途**：不受引擎管理的任务（如纸质工作）。

✅ 引擎**不追踪**此类任务的开始和完成，只是流程图上的标记。

### 4.2.6 Business Rule Task（业务规则任务） ✅

**用途**：向业务规则引擎提供输入，获取计算输出。

| 属性           | 类型   | 默认            | 说明     |
| -------------- | ------ | --------------- | -------- |
| implementation | string | `##unspecified` | 实现技术 |

### 4.2.7 Script Task（脚本任务） ✅

**用途**：引擎直接执行脚本。

| 属性             | 类型   | 说明                                             |
| ---------------- | ------ | ------------------------------------------------ |
| **scriptFormat** | string | 脚本格式（MIME 类型，如 `application/x-groovy`） |
| **script**       | string | 脚本内容（XML body）                             |

✅ **执行语义**：

- 引擎在 Task 开始时执行脚本
- 脚本执行完成 → Task 完成
- 脚本可访问流程变量

## 4.3 Sub-Process 类型

> 对应原书 §10.3.5（p.201-211）

### 4.3.1 Embedded Sub-Process（嵌入子流程） ✅

最普通的子流程，**作为流程图的局部容器**。

**特点**：

- 提供作用域（scope）：属性可见性、事务边界、异常处理范围、补偿范围
- 可以折叠（隐藏细节）或展开（显示内部）
- 内部可包含 Activities、Gateways、Events、Sequence Flows、Data Objects

**核心属性**：

| 属性             | 类型            | 默认  | 说明                     |
| ---------------- | --------------- | ----- | ------------------------ |
| triggeredByEvent | boolean         | false | 是否为 Event Sub-Process |
| artifacts        | Artifact [0..*] | —     | 内部 Artifact            |

**继承**：SubProcess 继承 Activity + FlowElementsContainer。

### 4.3.2 Event Sub-Process（事件子流程） ✅

**特点**：

- `triggeredByEvent=true`
- **不能有入向或出向 SequenceFlow**
- 必须有且仅一个 Start Event
- Start Event **必须有 trigger**（Message/Error/Escalation/Compensation/Conditional/Signal/Multiple）

**与父流程的关系**：

| 触发模式                         | 行为                                   |
| -------------------------------- | -------------------------------------- |
| **Interrupting**（中断型）       | 父流程被中断，Event Sub-Process 接管   |
| **Non-interrupting**（非中断型） | 父流程继续，Event Sub-Process 并行运行 |

✅ 用途：在子流程范围内捕获 Error / Escalation / Compensation / Timer 等事件。

### 4.3.3 Transaction（事务子流程） ✅

**特点**：通过事务协议（如 WS-Transaction）控制特殊行为。

| 属性 | 类型 | 说明 |
| --- | --- | --- |
| method | TransactionMethod | 事务方法（如 WS-AtomicTransaction、WS-BusinessActivity URI） |

**三种可能结果**：

| 结果 | 说明 |
| --- | --- |
| **Successful** | 正常完成，离开 Transaction |
| **Cancel**（取消） | 内部活动被取消，触发补偿，通过 Cancel Boundary Event 离开 |
| **Hazard**（异常） | 通过 Error Boundary Event 离开，**不触发补偿** |

⚠️ **关键约束**：

- Cancel End Event 只能在 Transaction Sub-Process 内使用
- Cancel Boundary Event 只能挂在 Transaction Sub-Process 边界

### 4.3.4 Ad-Hoc Sub-Process（即兴子流程） ✅

**特点**：内部 Activity **没有强制的顺序关系**，由执行者决定。

| 属性 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| **completionCondition** | Expression | — | **完成条件**，求值为 true 时终止 |
| ordering | `Parallel` \| `Sequential` | Parallel | 是否允许并行 |
| cancelRemainingInstances | boolean | true | 完成时是否取消运行中的实例 |

✅ **元素约束**：

- **必须有**：Activity
- **可以有**：Data Object / Sequence Flow / Association / Data Association / Group / Message Flow / Gateway / Intermediate Event
- **禁止有**：Start Event、End Event、Conversations、Choreography Activities

ℹ️ 引擎实现难度大，通常由 groupware 应用支持，BPMN 规范允许建模但很少实现。

## 4.4 Call Activity（调用活动）

> 对应原书 §10.3.6（p.212-216）

**用途**：在流程中**调用一个全局 Process 或 Global Task**，类似编程语言中的函数调用。

| 属性 | 类型 | 说明 |
| --- | --- | --- |
| **calledElement** | CallableElement [0..1] | **被调用的元素**（QName 引用，指向 Process 或 Global Task） |

### 4.4.1 CallableElement（可调用元素） ✅

抽象基类，子类：`Process` 和 `GlobalTask`。

| 属性 | 类型 | 说明 |
| --- | --- | --- |
| name | string | 名称 |
| supportedInterfaceRefs | Interface [0..*] | 提供的服务接口 |
| ioSpecification | InputOutputSpecification [0..1] | IO 规格 |
| ioBinding | InputOutputBinding [0..*] | IO 绑定到具体 Operation |

### 4.4.2 引擎执行语义 ✅

✅ **规范性要求**：

- Call Activity 的 IO Specification **必须与被调用元素的 IO Specification 完全匹配**
- 包括 DataInputs、DataOutputs、InputSets、OutputSets
- 执行控制权**转移到被调用元素**
- 被调用元素结束后，控制权返回 Call Activity

**Event 传播规则**：

- Error / Escalation 从被调用元素**传播到 Call Activity 边界**
- Call Activity 可在边界上挂 Boundary Event 捕获

**属性覆盖规则**：

- Call Activity 定义的 ResourceRole 会**覆盖**被调用元素的 ResourceRole
- 其他属性（如 Loop Characteristics）在 Call Activity 层独立

## 4.5 Global Task（全局任务）

> 对应原书 §10.3.7（p.216）

**用途**：定义**可复用的原子 Task**，可被任意 Call Activity 调用。

**类型**：

- GlobalTask（抽象基类）
- GlobalBusinessRuleTask
- GlobalScriptTask
- GlobalManualTask
- GlobalUserTask
- GlobalSendTask
- GlobalReceiveTask
- GlobalServiceTask

## 4.6 Resource Assignment（资源分配）

> 对应原书 §10.3.1（p.182）

### 4.6.1 ResourceRole（资源角色）

| 属性 | 类型 | 说明 |
| --- | --- | --- |
| resourceRef | Resource [0..1] | 引用具体资源 |
| resourceAssignmentExpression | ResourceAssignmentExpression [0..1] | 资源分配表达式 |
| resourceParameterBindings | ResourceParameterBinding [0..*] | 资源参数绑定 |

⚠️ `resourceRef` 和 `resourceAssignmentExpression` **互斥**，只能选一个。

### 4.6.2 资源分配表达式

通过 Expression 在运行时分配资源（如 `users(manager)` 返回所有经理）。

### 4.6.3 ResourceParameterBinding

为 Resource Query 提供参数（如 buyerName=订单上的客户名）。

## 4.7 引擎实现要点

### 4.7.1 Activity 生命周期（关键状态）

参考 §13.3.2，Activity 的核心状态：

```
            (创建)
              ↓
        ┌──────────┐
        │ AVAILABLE │ ← 等待 token 到达
        └─────┬────┘
              ↓
        ┌──────────┐
        │  ACTIVE  │ ← 执行中
        └─────┬────┘
              ↓
        ┌──────────┐
        │COMPLETE-ING│
        └─────┬────┘
              ↓
        ┌──────────┐
        │ COMPLETED │
        └──────────┘
              或
        ┌──────────┐
        │CANCELLED │ ← 被错误/取消中断
        └──────────┘
```

### 4.7.2 各 Task 类型的实现要点

| Task 类型        | 引擎需要做什么                                         |
| ---------------- | ------------------------------------------------------ |
| ServiceTask      | 通过 implementation 解析 SPI，调用 Operation，处理返回 |
| SendTask         | 准备 messageRef 载荷，通过消息中间件发出，立即完成     |
| ReceiveTask      | 注册消息订阅，等待匹配消息到达                         |
| UserTask         | 创建 task manager 中的任务，等待人工 complete 信号     |
| ManualTask       | 标记为不追踪，立即完成                                 |
| BusinessRuleTask | 调用规则引擎（如 DMN）                                 |
| ScriptTask       | 在沙箱中执行脚本，可访问流程变量                       |

### 4.7.3 SubProcess 实现要点

- **作用域管理**：维护子流程级的变量作用域
- **异常传播**：未捕获的 Error/Escalation 沿作用域链向上传播
- **事件订阅**：Event Sub-Process 在父作用域激活时订阅
- **Call Activity 数据映射**：通过 IO Specification + DataAssociation 做数据传递

### 4.7.4 边界事件挂载

```xml
<userTask id="task1">
  <boundaryEvent id="be1" attachedToRef="task1" cancelActivity="true">
    <timerEventDefinition>
      <timeDuration>PT1H</timeDuration>
    </timerEventDefinition>
  </boundaryEvent>
</userTask>
```

引擎要支持：

- 边界事件在 Activity 进入 ACTIVE 状态时**激活**
- 边界事件触发时根据 `cancelActivity` 决定是否中断宿主 Activity
- Activity 正常完成时**取消**所有未触发的边界事件订阅
