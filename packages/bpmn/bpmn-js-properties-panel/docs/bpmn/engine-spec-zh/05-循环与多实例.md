# 第 5 章 循环与多实例

> 对应原规范：Ch 10.3.8 Loop Characteristics（p.218-224）

## 5.1 概述

Activity 可以**重复执行**，由 `loopCharacteristics` 属性指定。BPMN 定义两种循环：

| 类型 | 中文 | 用途 |
| --- | --- | --- |
| StandardLoopCharacteristics | 标准循环 | while/for 循环（单实例反复执行） |
| MultiInstanceLoopCharacteristics | 多实例 | 并行/串行 N 个独立实例 |

`LoopCharacteristics` 是抽象基类。

## 5.2 Standard Loop（标准循环）

> 对应原书 §10.3.8（p.219）

### 5.2.1 属性

| 属性 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| **loopCondition** | Expression | — | **布尔条件**，true 时继续循环 |
| **testBefore** | boolean | false | true：循环开始前测试；false：循环结束后测试 |
| loopMaximum | integer | — | 最大迭代次数（可选 cap） |

### 5.2.2 执行语义

```
testBefore=true（前测）：
  while (loopCondition) {
    execute Activity;
    if (loopMaximum reached) break;
  }

testBefore=false（后测，默认）：
  do {
    execute Activity;
  } while (loopCondition && !loopMaximumReached);
```

### 5.2.3 实例属性

| 属性        | 类型    | 说明                         |
| ----------- | ------- | ---------------------------- |
| loopCounter | integer | 当前循环计数（引擎自动维护） |

### 5.2.4 引擎实现

✅ 关键点：

- 引擎维护 loopCounter，每次迭代递增
- loopMaximum 是硬上限，即使 condition 为 true 也必须停止
- 表达式可访问 loopCounter

## 5.3 Multi-Instance（多实例）

> 对应原书 §10.3.8（p.220）

### 5.3.1 核心属性

| 属性 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| **isSequential** | boolean | false | **true=串行，false=并行** |
| loopCardinality | Expression | — | 实例数量表达式 |
| loopDataInputRef | ItemAwareElement | — | 数据驱动的输入集合引用 |
| loopDataOutputRef | ItemAwareElement | — | 数据驱动的输出集合引用 |
| inputDataItem | DataInput | — | 每个实例的输入项 |
| outputDataItem | DataOutput | — | 每个实例的输出项 |
| **behavior** | `None`\|`One`\|`All`\|`Complex` | All | 完成时 token 产生策略 |
| completionCondition | Expression | — | 提前完成条件 |
| complexBehaviorDefinition | ComplexBehaviorDefinition [0..*] | — | Complex 模式下的行为定义 |
| oneBehaviorEventRef | EventDefinition | — | One 模式触发的事件 |
| noneBehaviorEventRef | EventDefinition | — | None 模式触发的事件 |

⚠️ **必需条件**：`loopCardinality` 和 `loopDataInputRef` **至少有一个**必须指定。

### 5.3.2 并行 vs 串行

| 模式                           | 标记方向  | 行为                   |
| ------------------------------ | --------- | ---------------------- |
| **并行**（isSequential=false） | 竖线（    |                        |     | ）  | 一次性创建所有 N 个实例，并行执行 |
| **串行**（isSequential=true）  | 横线（≡） | 一个完成后再创建下一个 |

### 5.3.3 数据驱动的多实例（推荐）

最常用模式：通过集合自动决定实例数。

**输入端**：

- `loopDataInputRef` 指向一个集合变量
- 集合中每个元素对应一个实例
- `inputDataItem` 是单实例能访问的"当前元素"

**输出端**：

- 每个实例产出 `outputDataItem`
- 引擎自动收集到 `loopDataOutputRef` 指向的集合

```xml
<serviceTask id="processOrderItems">
  <multiInstanceLoopCharacteristics isSequential="false"
                                    loopDataInputRef="orderItems">
    <inputDataItem name="item" />
    <outputDataItem name="result" />
    <completionCondition>
      ${numberOfCompletedInstances == numberOfInstances}
    </completionCondition>
  </multiInstanceLoopCharacteristics>
</serviceTask>
```

### 5.3.4 behavior 属性详解 ✅

控制**多实例完成时如何产生 token**：

| 取值 | 行为 |
| --- | --- |
| **None** | 每个内部实例完成时都抛出一个事件（默认 SignalEventDefinition） |
| **One** | 第一个内部实例完成时抛出 oneBehaviorEventRef 指定的事件 |
| **All**（默认） | 所有内部实例都完成后，产生一个 token |
| **Complex** | 通过 complexBehaviorDefinition 自定义控制 |

### 5.3.5 实例运行时属性 ✅

**外层实例（Multi-Instance Activity 本身）可访问**：

| 属性                        | 说明                          |
| --------------------------- | ----------------------------- |
| loopCounter                 | 当前实例序号（n 表示第 n 个） |
| numberOfInstances           | 总实例数                      |
| numberOfActiveInstances     | 当前活动实例数                |
| numberOfCompletedInstances  | 已完成实例数                  |
| numberOfTerminatedInstances | 已终止实例数                  |

ℹ️ **恒等式**：`numberOfActiveInstances + numberOfCompletedInstances + numberOfTerminatedInstances = numberOfInstances`

### 5.3.6 ComplexBehaviorDefinition（复杂行为定义）

| 属性      | 类型               | 说明               |
| --------- | ------------------ | ------------------ |
| condition | FormalExpression   | 求值为 true 时触发 |
| event     | ImplicitThrowEvent | 触发的事件         |

### 5.3.7 completionCondition（提前完成）

✅ 当 condition 求值为 true 时：

- 取消所有尚未完成的内部实例
- 产出 token

**典型用法**：`numberOfCompletedInstances >= 1`（任一实例完成即可），等价于"投票"。

## 5.4 引擎实现要点

### 5.4.1 标准循环

```java
class StandardLoopExecutor {
    void execute(ActivityInstance activity) {
        int counter = 0;
        while (true) {
            if (testBefore && !evaluateLoopCondition(counter)) break;
            if (counter >= loopMaximum) break;

            executeOnce(activity);
            counter++;

            if (!testBefore && !evaluateLoopCondition(counter)) break;
        }
    }
}
```

### 5.4.2 多实例（并行）

```java
class ParallelMultiInstanceExecutor {
    void execute(ActivityInstance outerInstance) {
        Collection<?> inputs = resolveCollection(loopDataInputRef);
        int n = inputs.size();

        // 一次性创建 N 个内部实例
        List<ActivityInstance> innerInstances = new ArrayList<>();
        for (Object item : inputs) {
            ActivityInstance inner = createInnerInstance(outerInstance, item);
            innerInstances.add(inner);
            executor.submit(() -> executeInner(inner));
        }

        // 等待所有完成或 completionCondition 触发
        waitForCompletion(outerInstance, innerInstances);
    }
}
```

### 5.4.3 多实例（串行）

```java
class SequentialMultiInstanceExecutor {
    void execute(ActivityInstance outerInstance) {
        Collection<?> inputs = resolveCollection(loopDataInputRef);
        Iterator<?> it = inputs.iterator();

        while (it.hasNext()) {
            if (evaluateCompletionCondition(outerInstance)) break;

            Object item = it.next();
            ActivityInstance inner = createInnerInstance(outerInstance, item);
            executeInner(inner); // 同步等待完成
        }
    }
}
```

### 5.4.4 输出收集

引擎需要：

- 为每个 `outputDataItem` 维护一个收集列表
- 内部实例完成时将输出加入列表
- 外层实例完成时将列表写入 `loopDataOutputRef`

### 5.4.5 边界事件与多实例的交互

- Boundary Event 可以挂在 Multi-Instance Activity 边界
- behavior=None/One 模式下，完成事件可被 Boundary 捕获
- 取消 Multi-Instance 时，要**同步取消所有内部实例**

## 5.5 常见陷阱

| 陷阱 | 说明 |
| --- | --- |
| 多实例 + 并发修改 | 多个内部实例并行写同一变量 → 用线程安全容器 |
| 数据驱动模式集合为空 | 创建 0 个实例，外层立即完成（注意区分"0 实例"和"未完成"） |
| 串行模式阻塞太久 | 内部实例若等待外部消息，会阻塞后续实例创建 |
| completionCondition 写错 | `${true}` 会立即触发，导致一个实例都没创建就完成 |
| loopMaximum=0 | 标准循环不会执行任何迭代，Activity 直接完成 |
