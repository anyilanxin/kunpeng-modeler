# 第 6 章 数据与变量

> 对应原规范：Ch 10.4 Items and Data（p.232-261）

## 6.1 Item-Aware Element（项感知元素）

> 对应原书 §10.4.1（p.232）

BPMN 中所有**存储或传递数据**的元素都继承自抽象基类 `ItemAwareElement`，相当于编程语言中的"变量"概念。

### 6.1.1 核心属性

| 属性 | 类型 | 说明 |
| --- | --- | --- |
| **itemSubjectRef** | ItemDefinition [0..1] | 数据结构定义（变量类型） |
| dataState | DataState [0..1] | 数据状态（如 "available"、"unavailable"） |

### 6.1.2 具体的 Item-Aware 元素

| 元素 | 中文 | 作用域 | 可视化 |
| --- | --- | --- | --- |
| **DataObject** | 数据对象 | Process / SubProcess | ✅ 显示 |
| DataObjectReference | 数据对象引用 | Process / SubProcess | ✅ 显示 |
| DataStore | 数据存储（持久化） | Definitions（全局） | ✅ 显示 |
| DataStoreReference | 数据存储引用 | Process / SubProcess | ✅ 显示 |
| **Property** | 属性 | Flow Element 内部 | ❌ 不显示 |
| **DataInput** | 数据输入 | Activity / Event 的 IO Spec | ✅ 显示 |
| **DataOutput** | 数据输出 | Activity / Event 的 IO Spec | ✅ 显示 |

## 6.2 DataObject（数据对象）

> 对应原书 §10.4.1（p.234）

### 6.2.1 属性

| 属性         | 类型    | 默认  | 说明     |
| ------------ | ------- | ----- | -------- |
| isCollection | boolean | false | 是否集合 |

### 6.2.2 生命周期与可见性 ✅

✅ **规范性要求**：

- DataObject 的生命周期**与所属 Process 或 SubProcess 绑定**
- 父容器实例化时，DataObject 也实例化
- 父容器销毁时，DataObject 也销毁
- **可见性规则**：DataObject 只能被其直接父容器和兄弟 FlowElement（含其子元素）访问

**示例层级**：

```
Process A
├── DataObject 1     (可被所有人访问)
├── Task A
├── SubProcess A
│   ├── DataObject 2 (只被 SubProcess A 和 Task B 访问)
│   └── Task B
└── SubProcess B
    ├── DataObject 3
    └── SubProcess C
        ├── DataObject 4
        └── Task C
```

### 6.2.3 DataObjectReference（数据对象引用）

✅ 用途：在流程图不同位置引用同一个 DataObject，可以**标注不同状态**（如 `[init]`、`[approved]`）。

| 属性          | 类型       | 说明                  |
| ------------- | ---------- | --------------------- |
| dataObjectRef | DataObject | 引用的目标 DataObject |

**命名约定**：`<DataObject 名> [<状态>]`，如 `Order [approved]`。

## 6.3 DataStore（数据存储）

> 对应原书 §10.4.1（p.237）

DataStore 用于**跨流程实例、跨流程定义共享的持久化数据**。

### 6.3.1 DataStore 属性

| 属性        | 类型    | 默认  | 说明                                 |
| ----------- | ------- | ----- | ------------------------------------ |
| name        | string  | —     | 名称                                 |
| capacity    | integer | —     | 容量上限                             |
| isUnlimited | boolean | false | 是否无限容量（true 时忽略 capacity） |

### 6.3.2 DataStoreReference

| 属性         | 类型      | 说明               |
| ------------ | --------- | ------------------ |
| dataStoreRef | DataStore | 指向全局 DataStore |

✅ DataStore 是 **RootElement**，在 `Definitions` 下定义，可被多个流程共享。

## 6.4 Property（属性）

> 对应原书 §10.4.1（p.238）

Property 是 FlowElement **内部**的变量，**不在流程图上显示**。

### 6.4.1 属性

| 属性           | 类型           | 说明   |
| -------------- | -------------- | ------ |
| name           | string         | 属性名 |
| itemSubjectRef | ItemDefinition | 类型   |

### 6.4.2 可见性规则 ✅

✅ 规则：Property 由其父 FlowElement 实例化，只能被父元素及其子元素访问。

## 6.5 InputOutputSpecification（输入输出规格）

> 对应原书 §10.4.1（p.240）

`InputOutputSpecification` 是 Activity / CallableElement 的**数据契约**。

### 6.5.1 核心属性

| 属性            | 类型              | 必需 | 说明                   |
| --------------- | ----------------- | ---- | ---------------------- |
| **dataInputs**  | DataInput [0..*]  | 否   | 数据输入列表（有序）   |
| **dataOutputs** | DataOutput [0..*] | 否   | 数据输出列表（有序）   |
| **inputSets**   | InputSet [1..*]   | ✅   | **至少一个 InputSet**  |
| **outputSets**  | OutputSet [1..*]  | ✅   | **至少一个 OutputSet** |

### 6.5.2 使用范围 ✅

✅ **规范性约束**：

- **可以定义** IO Spec 的：Task（所有类型）、CallableElement（Process、GlobalTask）
- **禁止定义** IO Spec 的：Embedded Sub-Process（但可通过 MultiInstanceLoopCharacteristics 间接定义）

## 6.6 DataInput / DataOutput

### 6.6.1 DataInput 属性

| 属性 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| name | string | — | 输入名 |
| isCollection | boolean | false | 是否集合 |
| inputSetRefs | InputSet [1..*] | — | 使用此输入的 InputSet（派生属性） |
| inputSetWithOptional | InputSet [0..*] | — | 此输入在哪些 InputSet 中可选 |
| inputSetWithWhileExecuting | InputSet [0..*] | — | 此输入在哪些 InputSet 中执行时求值 |

### 6.6.2 DataOutput 属性

与 DataInput 类似，但用于输出。

## 6.7 InputSet / OutputSet

### 6.7.1 InputSet（输入集合）

✅ 定义 Activity 启动前**必须满足的数据要求**。

| 属性                    | 类型             | 说明                           |
| ----------------------- | ---------------- | ------------------------------ |
| dataInputRefs           | DataInput [0..*] | 此 Set 包含的 DataInput        |
| optionalInputRefs       | DataInput [0..*] | 可选的 DataInput               |
| whileExecutingInputRefs | DataInput [0..*] | 执行期间可求值的 DataInput     |
| outputSetRefs           | OutputSet [0..*] | 此 InputSet 可对应的 OutputSet |

### 6.7.2 OutputSet（输出集合）

✅ 定义 Activity 完成后**产出的数据**。

| 属性                     | 类型              | 说明                         |
| ------------------------ | ----------------- | ---------------------------- |
| dataOutputRefs           | DataOutput [0..*] | 此 Set 包含的 DataOutput     |
| optionalOutputRefs       | DataOutput [0..*] | 可选的 DataOutput            |
| whileExecutingOutputRefs | DataOutput [0..*] | 执行期间可产出的 DataOutput  |
| inputSetRefs             | InputSet [0..*]   | 此 OutputSet 对应的 InputSet |

## 6.8 DataAssociation（数据关联）

> 对应原书 §10.4.1（p.250）

`DataAssociation` 定义**数据如何在 Item-Aware Element 之间流动**。

### 6.8.1 通用属性

| 属性           | 类型                    | 说明             |
| -------------- | ----------------------- | ---------------- |
| sourceRef      | ItemAwareElement [1..*] | 源（可多个）     |
| targetRef      | ItemAwareElement [1]    | 目标（恰好一个） |
| transformation | FormalExpression        | 数据转换表达式   |
| assignment     | Assignment [0..*]       | 复制赋值规则     |

### 6.8.2 Assignment（赋值）

| 属性 | 类型       | 说明       |
| ---- | ---------- | ---------- |
| from | Expression | 源表达式   |
| to   | Expression | 目标表达式 |

### 6.8.3 两个特化子类

- `DataInputAssociation`：目标必须是 Activity 的 DataInput
- `DataOutputAssociation`：源必须是 Activity 的 DataOutput

## 6.9 各 Task 类型的数据映射

| Task 类型    | 数据映射规则                                          |
| ------------ | ----------------------------------------------------- |
| ServiceTask  | DataInput 对应 inMessage；DataOutput 对应 outMessage  |
| SendTask     | DataInput 内容自动转入 messageRef 的 Message          |
| ReceiveTask  | messageRef 的 Message 自动转出到 DataOutput           |
| UserTask     | DataInput 是表单初始数据；DataOutput 是用户提交的数据 |
| ReceiveTask  | messageRef 载荷转出到 DataOutput                      |
| ScriptTask   | 脚本可读写 Property                                   |
| CallActivity | IO Spec 与 calledElement 的 IO Spec **必须完全一致**  |

## 6.10 执行语义

> 对应原书 §10.4.2（p.254）

### 6.10.1 DataAssociation 执行 ✅

```
Activity 启动前：
  for each DataInputAssociation:
    1. 求值 sourceRef 取到源值
    2. 若有 transformation，应用转换
    3. 若有 assignment，逐条执行 from→to
    4. 写入 targetRef 指向的 DataInput

Activity 执行期间：
  DataInput/Output 按 inputSetWithWhileExecuting/outputSetWithWhileExecuting 规则

Activity 完成后：
  for each DataOutputAssociation:
    1. 取出 DataOutput 的值
    2. 写入 targetRef 指向的目标（如 DataObject / Property）
```

### 6.10.2 XPath 访问 BPMN 数据

✅ Common Executable 子类**强制使用 XPath**。

| 访问对象          | XPath 路径                                 |
| ----------------- | ------------------------------------------ |
| Data Object       | `dataObjectName` 或 `dataObjectName.state` |
| Data Input        | `tns:dataInputName`                        |
| Data Output       | `tns:dataOutputName`                       |
| Property          | `propertyName`                             |
| Activity 实例属性 | `activityInstanceAttr`                     |

## 6.11 引擎实现要点

### 6.11.1 变量作用域模型

引擎内部建议建立分层作用域：

```java
class Scope {
    Scope parent;
    Map<String, Object> variables; // DataObjects + Properties

    Object getVariable(String name) {
        if (variables.containsKey(name)) return variables.get(name);
        if (parent != null) return parent.getVariable(name);
        throw new VariableNotDefinedException(name);
    }

    void setVariable(String name, Object value) {
        // 沿作用域链查找定义点
        Scope defining = findDefiningScope(name);
        defining.variables.put(name, value);
    }
}
```

### 6.11.2 数据流执行流程

```
1. Activity 即将执行
2. 引擎解析 IO Spec：
   - 检查 InputSet 是否满足（必需的 DataInput 都有值）
3. 执行 DataInputAssociation：
   - 从源（DataObject/Property/上级 Scope）取值
   - 应用 transformation（若有）
   - 写入 Activity 内部 DataInput
4. Activity 执行（业务逻辑）
5. Activity 产出 DataOutput
6. 执行 DataOutputAssociation：
   - 从 DataOutput 取值
   - 写入目标（DataObject/Property/上级 Scope）
```

### 6.11.3 集合类型处理

⚠️ `isCollection=true` 时的处理：

- 类型本身必须是集合类型，否则模型非法
- 引擎内部建议统一用 `List<T>` / `Set<T>` 表示
- 多实例 + 集合：每个实例处理一个元素，输出汇总

### 6.11.4 DataStore 集成

DataStore 是**跨流程实例共享**的，引擎需要：

- 单独的存储区（不是流程实例级别的）
- 并发控制（多流程实例同时读写）
- 持久化（流程引擎重启后数据不丢）

### 6.11.5 常见陷阱

| 陷阱 | 说明 |
| --- | --- |
| 跨 SubProcess 访问 DataObject | 不允许，必须通过 CallActivity IO Spec 或消息传递 |
| 忘记在 IO Spec 里声明 InputSet | InputSet 至少一个，即使是空的（表示无必需输入） |
| transformation 与 assignment 冲突 | 同时使用时按规范，transformation 先于 assignment |
| CallActivity IO Spec 不匹配 | calledElement 与 CallActivity 的 IO Spec 必须完全一致 |
