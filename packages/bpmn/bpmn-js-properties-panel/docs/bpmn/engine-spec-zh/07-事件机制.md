# 第 7 章 事件机制

> 对应原规范：Ch 10.5 Events（p.262-315）

## 7.1 概述

事件（Event）是流程执行过程中"发生的事情"，会影响流程走向。BPMN 用**圆圈**表示事件，按位置和形态区分类型。

### 7.1.1 三大主类型

| 类型               | 中文     | 形态     | 作用           |
| ------------------ | -------- | -------- | -------------- |
| Start Event        | 开始事件 | 单线圆圈 | 流程入口       |
| End Event          | 结束事件 | 粗线圆圈 | 流程出口       |
| Intermediate Event | 中间事件 | 双线圆圈 | 流程中间的事件 |

### 7.1.2 Catch vs Throw

| 类别 | 行为 | 包含 |
| --- | --- | --- |
| **Catch**（捕获） | **等待**触发器到来 | 所有 Start Event + 部分 Intermediate Event |
| **Throw**（抛出） | **产生**触发器 | 所有 End Event + 部分 Intermediate Event |

### 7.1.3 触发器分发策略

| 策略                          | 适用事件          | 行为               |
| ----------------------------- | ----------------- | ------------------ |
| Publication（发布）           | Message, Signal   | 跨作用域广播       |
| Direct Resolution（直接解析） | Link              | 直接连接两个节点   |
| Propagation（传播）           | Error, Escalation | 沿作用域链向上传播 |
| Cancellation（取消）          | Cancel            | 终止 + 补偿        |
| Compensation（补偿）          | Compensation      | 调用补偿处理器     |

## 7.2 通用属性

### 7.2.1 CatchEvent（捕获事件基类）

| 属性 | 类型 | 说明 |
| --- | --- | --- |
| **eventDefinitionRefs** | EventDefinition [0..*] | **可复用**的事件定义引用 |
| **eventDefinitions** | EventDefinition [0..*] | 内联的事件定义 |
| dataOutputs | DataOutput [0..*] | 输出数据 |
| dataOutputAssociations | DataOutputAssociation [0..*] | 输出数据关联 |
| outputSet | OutputSet [0..1] | 输出集 |
| **parallelMultiple** | boolean | **Parallel Multiple 模式**：所有触发器都必须满足 |

### 7.2.2 ThrowEvent（抛出事件基类）

| 属性                  | 类型                        | 说明                 |
| --------------------- | --------------------------- | -------------------- |
| eventDefinitionRefs   | EventDefinition [0..*]      | 可复用的事件定义引用 |
| eventDefinitions      | EventDefinition [0..*]      | 内联的事件定义       |
| dataInputs            | DataInput [0..*]            | 输入数据             |
| dataInputAssociations | DataInputAssociation [0..*] | 输入数据关联         |
| inputSet              | InputSet [0..1]             | 输入集               |

### 7.2.3 数据携带 ✅

✅ **规范性要求**：Message / Escalation / Error / Signal / Multiple 事件可以**携带数据**。

- Throw Event 通过 DataInput 装载数据
- Catch Event 通过 DataOutput 接收数据
- 每个 EventDefinition 对应一个 DataInput/Output

## 7.3 Start Event（开始事件）

> 对应原书 §10.5.2（p.267-275）

### 7.3.1 通用语义 ✅

✅ **规范性要求**：

- Start Event **不能有入向 SequenceFlow**
- Start Event 是可选的（没有时，所有无入向的 FlowObject 都启动并行路径）
- 一个 Process 可以有**多个 Start Event**，每个独立触发产生流程实例
- 触发时**为每条出向 SequenceFlow 产生一个 token**

⚠️ **特别约束**：

- 若有 End Event，则必须有 Start Event
- 若没有 Start Event，隐式 Start Event **不能有 trigger**
- Compensation Activity 不算正常 flow，启动时不被实例化

### 7.3.2 顶级 Process 的 Start Event 类型

| Trigger               | 描述                       | 中断？ |
| --------------------- | -------------------------- | ------ |
| **None**              | 无 trigger，用于同步调用   | —      |
| **Message**           | 接收 Message 触发          | —      |
| **Timer**             | 定时触发                   | —      |
| **Conditional**       | 条件为 true 触发           | —      |
| **Signal**            | 接收广播 Signal 触发       | —      |
| **Multiple**          | 多 trigger，任一满足即可   | —      |
| **Parallel Multiple** | 多 trigger，全部满足才触发 | —      |

### 7.3.3 Sub-Process 的 Start Event

✅ 嵌入式 Sub-Process **只能用 None Start Event**（其他类型无意义，因为父流程通过 token 传递触发）。

### 7.3.4 Event Sub-Process 的 Start Event

| Trigger           | 是否可中断           |
| ----------------- | -------------------- |
| Message           | ✅ 可中断 / 可不中断 |
| Timer             | ✅ 可中断 / 可不中断 |
| Escalation        | ✅ 可中断 / 可不中断 |
| **Error**         | **只能中断**         |
| Compensation      | 不适用（特殊处理）   |
| Conditional       | ✅ 可中断 / 可不中断 |
| Signal            | ✅ 可中断 / 可不中断 |
| Multiple          | ✅ 可中断 / 可不中断 |
| Parallel Multiple | ✅ 可中断 / 可不中断 |

### 7.3.5 isInterrupting 属性

| 属性           | 类型    | 默认 | 说明                                       |
| -------------- | ------- | ---- | ------------------------------------------ |
| isInterrupting | boolean | true | 仅对 Event Sub-Process 的 Start Event 有效 |

✅ **特殊规则**：Error 始终中断；Compensation 不适用。

## 7.4 End Event（结束事件）

> 对应原书 §10.5.3（p.275-278）

### 7.4.1 语义 ✅

✅ **规范性要求**：

- End Event **不能有出向 SequenceFlow**
- End Event 消耗 token
- Process 必须**所有 token 都消耗完**才算完成
- 一个 Process 可以有**多个 End Event**

### 7.4.2 九种 End Event 类型

| Result           | 描述                                                 |
| ---------------- | ---------------------------------------------------- |
| **None**         | 无 result，正常结束                                  |
| **Message**      | 向外部 Participant 发送 Message                      |
| **Error**        | 抛出 Error，沿作用域链寻找 Boundary Error Event 捕获 |
| **Escalation**   | 抛出 Escalation，不影响其他并行 token                |
| **Cancel**       | 仅用于 Transaction Sub-Process 内，触发取消          |
| **Compensation** | 触发补偿，对已完成 Activity 反向执行补偿             |
| **Signal**       | 广播 Signal 给所有感兴趣的 Process                   |
| **Terminate**    | **立即终止整个 Process 实例**，包括所有多实例        |
| **Multiple**     | 多个 result 同时发生（如同时发多个 Message）         |

### 7.4.3 Terminate End Event 行为 ⭐

✅ **特别强调**：

- 立即结束当前 Process 范围内**所有**活动
- **包括所有多实例的内部实例**
- **不触发补偿**
- 不执行 Event 处理

⚠️ **范围**：Terminate 仅影响**当前层级**（顶层 Process 或当前 Sub-Process），不影响父流程。

## 7.5 Intermediate Event（中间事件）

> 对应原书 §10.5.4（p.278-288）

### 7.5.1 两种使用方式

1. **正常流中**：可以 Catch 或 Throw
2. **挂在 Activity 边界**：只能 Catch（即 Boundary Event）

### 7.5.2 正常流中的 10 种 Intermediate Event

| Trigger           | Catch/Throw | 用途                       |
| ----------------- | ----------- | -------------------------- |
| None              | Throw       | 仅作流程标记，不触发任何事 |
| Message           | Catch/Throw | 接收/发送消息              |
| Timer             | Catch       | 定时延迟                   |
| Escalation        | Throw       | 抛出升级                   |
| Compensation      | Throw       | 触发补偿                   |
| Conditional       | Catch       | 等待条件成立               |
| **Link**          | Catch/Throw | **流程内跳转**（goto）     |
| Signal            | Catch/Throw | 接收/广播信号              |
| Multiple          | Catch/Throw | 任一/全部                  |
| Parallel Multiple | Catch       | 全部满足                   |

### 7.5.3 Link Event 详解 ⭐

Link Event 是 BPMN 内置的 **goto 机制**：

- Pair 出现：Throw Link（源） + Catch Link（目标）
- **只能在同一 Process 层级使用**（不能跨 Sub-Process）
- 多个 Throw 可以指向同一个 Catch
- 用途：避免长连线、跨页连接、循环

## 7.6 Boundary Event（边界事件）

> 对应原书 §10.5.4（p.283-287）

### 7.6.1 概念

Boundary Event 是**挂在 Activity 边界上的 Catch Intermediate Event**，用于捕获该 Activity 执行期间发生的特定事件。

### 7.6.2 核心属性

| 属性               | 类型     | 默认    | 说明                            |
| ------------------ | -------- | ------- | ------------------------------- |
| **attachedToRef**  | Activity | ✅ 必需 | **宿主 Activity**               |
| **cancelActivity** | boolean  | true    | 触发时是否**中断**宿主 Activity |

### 7.6.3 Interrupting vs Non-interrupting

| 模式 | 行为 |
| --- | --- |
| **Interrupting**（cancelActivity=true） | 中断宿主 Activity，token 走向 Boundary Event 的出向流 |
| **Non-interrupting**（cancelActivity=false） | 宿主继续执行，Boundary Event 产生新 token 走自己的路 |

### 7.6.4 边界事件类型

| Trigger           | 是否支持中断/非中断    |
| ----------------- | ---------------------- |
| Message           | ✅ 两种都支持          |
| Timer             | ✅ 两种都支持          |
| Escalation        | ✅ 两种都支持          |
| **Error**         | **只支持中断**         |
| Cancel            | 中断（仅 Transaction） |
| Compensation      | 特殊（不挂边界）       |
| Conditional       | ✅ 两种都支持          |
| Signal            | ✅ 两种都支持          |
| Multiple          | ✅ 两种都支持          |
| Parallel Multiple | ✅ 两种都支持          |

## 7.7 十二种 EventDefinition 详解

> 对应原书 §10.5.5（p.289-303）

### 7.7.1 CancelEventDefinition

- 仅用于 Transaction Sub-Process
- 触发事务取消和补偿

### 7.7.2 CompensationEventDefinition

| 属性              | 类型            | 说明                      |
| ----------------- | --------------- | ------------------------- |
| activityRef       | Activity [0..1] | 指定要补偿的具体 Activity |
| waitForCompletion | boolean         | 是否等待补偿完成          |

### 7.7.3 ConditionalEventDefinition

| 属性          | 类型       | 说明         |
| ------------- | ---------- | ------------ |
| **condition** | Expression | **触发条件** |

✅ **规范性要求**：条件**必须先变 false 再变 true** 才能再次触发。

### 7.7.4 ErrorEventDefinition

| 属性          | 类型           | 说明                         |
| ------------- | -------------- | ---------------------------- |
| **errorCode** | string         | **错误代码**（用于匹配捕获） |
| structureRef  | ItemDefinition | 错误载荷结构                 |

### 7.7.5 EscalationEventDefinition

| 属性               | 类型           | 说明                         |
| ------------------ | -------------- | ---------------------------- |
| **escalationCode** | string         | **升级代码**（用于匹配捕获） |
| structureRef       | ItemDefinition | 升级载荷结构                 |

### 7.7.6 LinkEventDefinition

| 属性     | 类型                       | 说明                        |
| -------- | -------------------------- | --------------------------- |
| **name** | string                     | **Link 名称**（配对匹配用） |
| source   | LinkEventDefinition [0..*] | 源（自动派生）              |
| target   | LinkEventDefinition [0..1] | 目标（自动派生）            |

### 7.7.7 MessageEventDefinition

| 属性           | 类型      | 说明               |
| -------------- | --------- | ------------------ |
| **messageRef** | Message   | **关联的 Message** |
| operationRef   | Operation | 关联的 Operation   |

### 7.7.8 SignalEventDefinition

| 属性          | 类型   | 说明              |
| ------------- | ------ | ----------------- |
| **signalRef** | Signal | **关联的 Signal** |

ℹ️ Signal 是**广播式**的，无特定目标，所有感兴趣的 Catch 都能接收。

### 7.7.9 TerminateEventDefinition

无特殊属性，仅表示"立即终止当前作用域的所有活动"。

### 7.7.10 TimerEventDefinition

| 属性             | 类型       | 说明                         |
| ---------------- | ---------- | ---------------------------- |
| **timeDate**     | Expression | **特定时间点**（ISO 8601）   |
| **timeDuration** | Expression | **持续时间**（如 `PT1H30M`） |
| **timeCycle**    | Expression | **循环周期**（如 `R5/PT1H`） |

✅ 三者**互斥**，只能指定一个。

### 7.7.11 Multiple 与 Parallel Multiple

不是独立的 EventDefinition，而是由 CatchEvent/ThrowEvent **同时引用多个 EventDefinition** 实现的。

- Multiple：任一触发即可（默认）
- Parallel Multiple：`parallelMultiple=true`，必须全部触发

## 7.8 事件处理规则 ✅

> 对应原书 §10.5.6（p.304-310）

### 7.8.1 Start Event 处理

- 顶级 Process 的 Start Event 触发 → **创建新的流程实例**
- Sub-Process 的 Start Event 触发 → 子流程开始执行
- Event Sub-Process 的 Start Event 触发 → 根据是否中断决定父流程命运

### 7.8.2 正常流中的 Intermediate Event 处理

- Throw Event：立即抛出，token 继续
- Catch Event：等待，触发后 token 继续

### 7.8.3 Boundary Event 处理

✅ **核心流程**：

1. 宿主 Activity 进入 ACTIVE 状态时，激活 Boundary Event 订阅
2. 触发器到来时，根据 `cancelActivity`：
   - true：**中断**宿主 Activity（取消所有内部执行）
   - false：宿主继续，Boundary Event 产生**新的并行 token**
3. token 从 Boundary Event 的出向 SequenceFlow 离开

### 7.8.4 Event Sub-Process 处理

类似 Boundary Event，但 Event Sub-Process 是**完整子流程**，不是单个 Event。

### 7.8.5 中断型 Event 清单

只支持中断的 Event：

- Error Event（任何位置）
- Cancel Event（Transaction 边界）
- Terminate End Event

可中断可不中断的：Message、Timer、Escalation、Conditional、Signal、Multiple、Parallel Multiple。

### 7.8.6 非中断型 Event 行为

✅ 关键：触发时**不取消**宿主 Activity / 父作用域，产生**新的并行 token**走 Event 的出向流。可以被多次触发。

## 7.9 Scopes（事件作用域）

> 对应原书 §10.5.7（p.310）

Event 的可见性由**作用域层次**决定：

```
Process (顶层)
├── Activity A
│   └── [BoundaryEvent on A: Error] ← 能捕获 Activity A 内部抛出的 Error
├── Sub-Process B
│   ├── [EventSubProcess: Error] ← 能捕获 Sub-Process B 内部的 Error
│   └── Activity C
└── [BoundaryEvent on Process: Signal] ← 能捕获 Process 内的 Signal
```

✅ **传播规则**：Error/Escalation 沿作用域链向上传播，被**最近的**能捕获的 Event 捕获。

## 7.10 引擎实现要点

### 7.10.1 Event 订阅机制

引擎需要维护**运行时的 Event 订阅表**：

```java
class EventSubscription {
    String eventType;        // message, signal, timer, error...
    String eventDefinitionId;
    String activityInstanceId;
    String processInstanceId;
    Map<String, Object> payload;  // for correlation
}

class EventSubscriptionManager {
    // 创建订阅（Activity 进入 ACTIVE 时）
    void createSubscription(BoundaryEvent event, ActivityInstance host);

    // 触发事件（外部消息到达时）
    void triggerEvent(String eventType, String eventDefinitionId, Map<String, Object> payload);

    // 取消订阅（Activity 完成时）
    void cancelSubscription(String activityInstanceId);
}
```

### 7.10.2 Timer 实现

| 模式         | 实现                                                       |
| ------------ | ---------------------------------------------------------- |
| timeDate     | ScheduledExecutorService.schedule(date - now)              |
| timeDuration | ScheduledExecutorService.schedule(duration)                |
| timeCycle    | ScheduledExecutorService.scheduleAtFixedRate / 自定义 cron |

### 7.10.3 Message + Correlation 联动

Message Catch Event 触发时：

1. 提取 CorrelationProperty 值
2. 匹配 CorrelationKey 实例
3. 找到对应的 ProcessInstance 和等待中的 Event
4. 写入 payload，触发 Event

### 7.10.4 Signal 广播

Signal 是**进程级广播**：

- 所有同 engine 实例的 Catch Signal Event 都能收到
- 跨 ProcessInstance、跨 ProcessDefinition
- 需要广播机制（如 Spring Event、Akka broadcast、Redis pub/sub）

### 7.10.5 中断 vs 非中断的实现

```java
void onBoundaryEventTriggered(BoundaryEvent event, ActivityInstance host) {
    if (event.isCancelActivity()) {
        // 中断：取消宿主
        activityManager.cancel(host);
    } else {
        // 非中断：宿主继续，新建并行 token
        tokenManager.createParallelToken(event.getOutgoing());
    }
    // 都要走 boundary event 的出向流
    tokenManager.traverse(event);
}
```

### 7.10.6 常见陷阱

| 陷阱 | 说明 |
| --- | --- |
| Error 未被捕获 | 默认中断整个流程实例 |
| Non-interrupting 触发多次 | 每次都创建新 token，可能产生意外并行 |
| Terminate End 在 Sub-Process | 只终止当前 Sub-Process，父流程继续 |
| Multiple Start Event | 任一触发即启动新实例，可能产生多个并发实例 |
| Conditional Event 的条件变化检测 | 引擎需要轮询或事件驱动来判断条件变化 |
| Compensation Event 触发顺序 | 逆序补偿，需要正确维护 Activity 完成历史 |
