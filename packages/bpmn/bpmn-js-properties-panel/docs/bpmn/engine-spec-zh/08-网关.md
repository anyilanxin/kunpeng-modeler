# 第 8 章 网关

> 对应原规范：Ch 10.6 Gateways（p.316-330）

## 8.1 概述

Gateway（网关）用于**控制 SequenceFlow 的汇聚和分叉**。Gateway 不代表"工作"，对流程的成本/时间等运营指标**零影响**。

### 8.1.1 通用属性

| 属性 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| **gatewayDirection** | `Unspecified`\|`Converging`\|`Diverging`\|`Mixed` | Unspecified | 网关方向 |

✅ **方向约束**：

- `Converging`：可以多入向，**最多 1 出向**
- `Diverging`：可以多出向，**最多 1 入向**
- `Mixed`：必须多入向 + 多出向
- `Unspecified`：无约束

### 8.1.2 SequenceFlow 连接规则 ✅

✅ **规范性要求**：

- Gateway 必须有**多个入向或多个出向**（必须汇聚或分叉）
- 没有入向且无 Start Event 时，分叉行为在流程实例化时执行

## 8.2 Exclusive Gateway（排他网关 / XOR）

> 对应原书 §10.6.2（p.319）

### 8.2.1 行为

**分叉（Diverging）**：按条件选择**一条**路径。

✅ **规范性要求**：

- 对每条出向 SequenceFlow 的 conditionExpression 求值
- **只有一条**路径被选中
- 可指定 `default` 流（无 expression），所有条件都不满足时走这条
- **没有 default 且所有条件都不满足** → 抛出运行时异常

**汇聚（Converging）**：每个到达的 token 直接路由到出向流，**不同步**。

### 8.2.2 属性

| 属性    | 类型                | 说明       |
| ------- | ------------------- | ---------- |
| default | SequenceFlow [0..1] | 默认出向流 |

### 8.2.3 实现要点

```java
void executeDiverging(ExclusiveGateway gw, Token token) {
    SequenceFlow chosen = null;
    for (SequenceFlow out : gw.getOutgoing()) {
        if (out == gw.getDefault()) continue;
        if (evaluate(out.getCondition(), token)) {
            chosen = out;
            break;
        }
    }
    if (chosen == null) {
        chosen = gw.getDefault();
        if (chosen == null) throw new RuntimeException("No path matched");
    }
    token.traverse(chosen);
}

void executeConverging(ExclusiveGateway gw, Token token) {
    // 直接放行，不等待其他 token
    token.traverse(gw.getOutgoing().get(0));
}
```

## 8.3 Inclusive Gateway（包容网关 / OR）

> 对应原书 §10.6.3（p.321）

### 8.3.1 行为

**分叉**：所有条件**都求值**，**满足条件的所有路径**都走。

✅ **规范性要求**：

- 对每条出向 SequenceFlow 的 conditionExpression 求值
- **满足 true 的所有路径**都产生 token（可能 0 到 N 条）
- 可指定 default（所有条件都不满足时）
- 设计时应保证至少一条路径被选中

**汇聚**：等待**所有可能同步的 token**。

⚠️ **同步语义复杂**：Inclusive Gateway 的汇聚需要根据**分叉时的状态**判断要等待哪些 token。

### 8.3.2 属性

| 属性    | 类型                | 说明       |
| ------- | ------------------- | ---------- |
| default | SequenceFlow [0..1] | 默认出向流 |

### 8.3.3 实现要点

```java
void executeDiverging(InclusiveGateway gw, Token token) {
    List<SequenceFlow> chosen = new ArrayList<>();
    for (SequenceFlow out : gw.getOutgoing()) {
        if (out == gw.getDefault()) continue;
        if (evaluate(out.getCondition(), token)) {
            chosen.add(out);
        }
    }
    if (chosen.isEmpty()) {
        if (gw.getDefault() != null) chosen.add(gw.getDefault());
        else throw new RuntimeException("No path matched");
    }
    for (SequenceFlow out : chosen) {
        token.fork(out);
    }
}
```

⚠️ **汇聚难点**：引擎需要维护"上游分叉时哪些路径被激活"的信息，才能正确判断同步完成。

## 8.4 Parallel Gateway（并行网关 / AND）

> 对应原书 §10.6.4（p.322）

### 8.4.1 行为

**分叉**：**所有出向流**都产生 token，**不检查条件**。

**汇聚**：**等待所有入向流**都到达 token，然后产生一个 token 到出向流。

✅ **最常用**的同步原语。

### 8.4.2 属性

无额外属性。

### 8.4.3 实现要点

```java
void executeDiverging(ParallelGateway gw, Token token) {
    for (SequenceFlow out : gw.getOutgoing()) {
        token.fork(out);  // 每条出向流都产生一个新 token
    }
}

void executeConverging(ParallelGateway gw, Token token) {
    TokenJoin join = joinManager.getOrCreate(gw, token.getParent());
    join.addToken(token);
    if (join.allArrived()) {
        Token merged = join.merge();
        merged.traverse(gw.getOutgoing().get(0));
    }
}
```

## 8.5 Complex Gateway（复杂网关）

> 对应原书 §10.6.5（p.324）

### 8.5.1 行为

**自定义同步行为**，通过 `activationCondition` 描述。

**示例**：5 条入向流中"3 条到达即可激活"。

### 8.5.2 属性

| 属性 | 类型 | 说明 |
| --- | --- | --- |
| **activationCondition** | Expression | **激活条件**（如 `${tokenCount >= 3}`） |
| default | SequenceFlow [0..1] | 默认出向流 |

### 8.5.3 实例运行时属性

| 属性                | 类型    | 说明                                      |
| ------------------- | ------- | ----------------------------------------- |
| activationCount     | integer | 入向流上当前的 token 数                   |
| **waitingForStart** | boolean | 内部状态：true 等待激活，false 等待 reset |

### 8.5.4 Reset 行为

激活后若还有 token 到达，会触发 **reset**，再次产生 token。引擎实现复杂，**很少使用**。

## 8.6 Event-Based Gateway（基于事件的网关）

> 对应原书 §10.6.6（p.326）

### 8.6.1 行为

**等待后续事件触发**决定路径，是事件驱动的分支选择。

✅ **核心特点**：

- 出向流连接的是 **Intermediate Event 或 Receive Task**
- **每个分支**等待不同的 Event 触发
- **第一个触发的事件胜出**（race condition）
- 其他分支立即失效

### 8.6.2 属性

| 属性 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| **instantiate** | boolean | false | 是否作为流程启动入口 |
| **eventGatewayType** | `Exclusive`\|`Parallel` | Exclusive | 实例化时的行为 |

### 8.6.3 配置约束 ✅

✅ **规范性要求**：

- **必须 2 条以上出向流**
- 出向流**不能有 conditionExpression**
- 出向流目标只能是 **Intermediate Event** 或 **Receive Task**（不能混用）
- Receive Task 不能再挂 Boundary Event
- 允许的 Intermediate Event trigger：Message、Signal、Timer、Conditional、Multiple
- **不允许**的 trigger：Error、Cancel、Compensation、Link
- 目标元素不能再有其他入向流

### 8.6.4 Exclusive 模式（默认）

✅ 行为：第一个触发的事件"获胜"，其他分支被**取消**。

### 8.6.5 Parallel 模式

✅ 必须设 `instantiate=true`，作为流程启动入口。

- 第一个事件触发 → 启动流程
- 其他分支**继续等待**，必须全部触发才能完成流程
- 所有 Message 必须**共享 Correlation 信息**

### 8.6.6 实现要点

```java
void executeEventBasedGateway(EventBasedGateway gw, Token token) {
    // 为每条出向流的目标 Event 创建订阅
    List<EventSubscription> subscriptions = new ArrayList<>();
    for (SequenceFlow out : gw.getOutgoing()) {
        CatchEvent target = (CatchEvent) out.getTarget();
        EventSubscription sub = subscribe(target, token);
        subscriptions.add(sub);
    }

    // 注册回调：第一个触发时取消其他
    onFirstTriggered(subscriptions, (winner) -> {
        subscriptions.stream()
            .filter(s -> s != winner)
            .forEach(EventSubscription::cancel);
        token.traverse(winner.getSequenceFlow());
    });
}
```

## 8.7 五种网关对比

| 网关 | 分叉行为 | 汇聚行为 | 选路径依据 | 是否同步 |
| --- | --- | --- | --- | --- |
| **Exclusive (XOR)** | 选 1 条 | 不同步 | 数据条件 | ❌ |
| **Inclusive (OR)** | 选 0..N 条 | 同步已激活的 | 数据条件 | ✅ |
| **Parallel (AND)** | 全选 | 全部同步 | 无条件 | ✅ |
| **Complex** | 按条件 | 按激活条件 | 自定义表达式 | ✅ |
| **Event-Based** | 等 1 个事件 | 不适用（只分叉） | 第一个事件 | ❌ |

## 8.8 引擎实现要点

### 8.8.1 Token 同步管理器

```java
interface TokenJoinManager {
    // 在汇聚网关上注册一个 token 到达
    TokenJoin joinConverging(Gateway gateway, ScopeInstance scope);

    // 判断是否所有需要的 token 都已到达
    boolean isComplete(TokenJoin join);

    // 合并 token，产生新的下行 token
    Token merge(TokenJoin join);
}
```

### 8.8.2 各 Gateway 的状态存储

| Gateway              | 是否需要状态 | 状态内容                         |
| -------------------- | ------------ | -------------------------------- |
| Exclusive            | ❌ 无状态    | —                                |
| Inclusive Diverging  | ❌ 无状态    | —                                |
| Inclusive Converging | ✅ 需要状态  | 已到达的 token + 上游分叉历史    |
| Parallel Converging  | ✅ 需要状态  | 已到达的 token 数                |
| Complex              | ✅ 需要状态  | waitingForStart、activationCount |
| Event-Based          | ✅ 需要状态  | 已创建的 EventSubscription 集合  |

### 8.8.3 死锁与活锁防范

⚠️ **常见问题**：

- Inclusive Converging 等待永远不会到达的 token（上游 Inclusive Diverging 没激活某条路径）
- Parallel Converging 死锁（某条入向流被取消）
- Event-Based Gateway 永远等不到事件

**建议**：

- 引擎提供**超时检测**机制
- 流程定义层面避免不可达路径
- 提供诊断 API：查询当前等待中的 join

### 8.8.4 默认流的处理

- Exclusive / Inclusive Gateway 才有 default
- default 流**不能有 conditionExpression**（即使有也忽略）
- 没有 default 且无匹配条件 → 运行时异常

### 8.8.5 Inclusive Converging 的实现技巧

为正确判断"哪些 token 需要等待"，引擎需要：

1. 流程定义层面**静态分析**：哪些 SequenceFlow 是某个 Inclusive Gateway 的可能路径
2. 运行时跟踪：到达 Converging 时，知道**哪些上游路径已被激活**
3. 同步完成：所有已激活路径的 token 都到达后，才向下流转
