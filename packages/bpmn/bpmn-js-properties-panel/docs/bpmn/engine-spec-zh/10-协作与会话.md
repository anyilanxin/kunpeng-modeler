# 第 10 章 协作与会话

> 对应原规范：Ch 9 Collaboration（p.137-168）

⚠️ **重要提示**：原规范明确说明本章**不是 Process Execution Conformance 的必需内容**。但若引擎要支持多 Pool / 跨流程通信，需要掌握本章。

## 10.1 Collaboration 概述

`Collaboration` 是一组 Participant（以 Pool 形式显示）+ 它们之间的 Message Flow，描述**多个流程之间的交互**。

### 10.1.1 核心属性

| 属性 | 类型 | 说明 |
| --- | --- | --- |
| name | string | 协作名称 |
| **participants** | Participant [0..*] | **参与者列表**（显示为 Pool） |
| **messageFlow** | MessageFlow [0..*] | **消息流列表** |
| conversations | ConversationNode [0..*] | 会话节点 |
| conversationLinks | ConversationLink [0..*] | 会话连接 |
| artifacts | Artifact [0..*] | 工件 |
| choreographyRef | Choreography [0..*] | 引用的 Choreography |
| correlationKeys | CorrelationKey [0..*] | 关联键 |
| **isClosed** | boolean = false | **true**：除已建模的 Message Flow 外**不允许**其他消息；**false**：允许 |

### 10.1.2 Definitional Collaboration

每个 Process 可以有一个 **definitional Collaboration**（定义性协作），描述这个 Process 与外部的通信。引擎通过它理解 Service/Send/Receive Task 的对端是谁。

## 10.2 Pool 与 Participant

### 10.2.1 Participant（参与者）

| 属性 | 类型 | 说明 |
| --- | --- | --- |
| name | string [0..1] | 名称 |
| **processRef** | Process [0..1] | **关联的 Process**（Pool 内的内容） |
| partnerRoleRef | PartnerRole [0..*] | 角色引用 |
| partnerEntityRef | PartnerEntity [0..*] | 实体引用 |
| interfaceRef | Interface [0..*] | 支持的接口 |
| participantMultiplicity | ParticipantMultiplicity [0..1] | 多重性（多个实例） |
| endPointRefs | EndPoint [0..*] | 服务端点 |

### 10.2.2 三种 Pool 形态

| 形态 | 说明 |
| --- | --- |
| **Black Box**（黑盒） | 不含 Process，只有边界。Message Flow 连到 Pool 边界 |
| **White Box**（白盒） | 含 Process，能看到内部 Activity。Message Flow 可连到具体 Activity |
| **Main Pool**（主 Pool） | 表示"自己"的流程，**可不画边界** |

### 10.2.3 ParticipantMultiplicity

| 属性    | 默认 | 说明                      |
| ------- | ---- | ------------------------- |
| minimum | 0    | 最少参与者数              |
| maximum | 1    | 最多参与者数（≥ minimum） |

✅ 用于"一个 Pool 代表多个实例"的场景，如"供应商 Pool"代表多家供应商。

### 10.2.4 PartnerEntity vs PartnerRole

| 元素          | 含义                       | 示例                     |
| ------------- | -------------------------- | ------------------------ |
| PartnerEntity | **具体实体**（公司、组织） | "阿里巴巴"、"腾讯"       |
| PartnerRole   | **抽象角色**（功能定位）   | "买家"、"卖家"、"制造商" |

一个 Participant 可同时关联两者。

### 10.2.5 ParticipantAssociation

用于**两个含 Participant 的模型间的映射**（如 Collaboration 引用 Choreography 时）。

| 属性                | 类型        | 说明                   |
| ------------------- | ----------- | ---------------------- |
| innerParticipantRef | Participant | 内部模型的 Participant |
| outerParticipantRef | Participant | 外部模型的 Participant |

## 10.3 Message Flow（消息流）

### 10.3.1 概念

`MessageFlow` 表示**两个 Pool 之间的消息传递**。**与 SequenceFlow 不同**：

- SequenceFlow：同一 Pool 内的执行顺序
- MessageFlow：跨 Pool 的通信

### 10.3.2 核心约束 ✅

✅ **规范性要求**：

- MessageFlow **必须连接两个不同的 Pool**
- 不能连接同一 Pool 内的两个对象
- 源和目标只能是：Pool/Participant、Activity、Event

### 10.3.3 属性

| 属性           | 类型            | 说明                            |
| -------------- | --------------- | ------------------------------- |
| name           | string          | 名称                            |
| **sourceRef**  | InteractionNode | 源（Pool / Activity / Event）   |
| **targetRef**  | InteractionNode | 目标（Pool / Activity / Event） |
| **messageRef** | Message [0..1]  | 携带的 Message                  |

### 10.3.4 InteractionNode

`InteractionNode` 是抽象的"可连接 Message Flow 的点"，具体实现是 Pool、Activity、Event。

### 10.3.5 MessageFlowAssociation

用于两个含 MessageFlow 的模型间映射（如 Collaboration ↔ Choreography）。

## 10.4 Conversation（会话）

> 对应原书 §9.5（p.153）

### 10.4.1 概念

`Conversation` 是**一组共享特定目的的 Message Flow 集合**。例如所有处理"订单"的 Message Flow 可以归到一个 Conversation。

### 10.4.2 四种 ConversationNode

| 类型                    | 说明                                     |
| ----------------------- | ---------------------------------------- |
| **Conversation**        | 普通会话                                 |
| **Sub-Conversation**    | 子会话（嵌套）                           |
| **Call Conversation**   | 调用全局 Conversation                    |
| **Global Conversation** | 全局可复用的 Conversation（RootElement） |

### 10.4.3 ConversationLink

连接 Conversation 与 Participant / Flow Element，表示"这个元素属于这个会话"。

### 10.4.4 Conversation 关联 Correlation

每个 Conversation 可以关联 CorrelationKey，用于消息路由。

## 10.5 Process within Collaboration

Process 在 Collaboration 中通过 Pool 显示。

✅ **每个 Process 都可以有一个 definitional Collaboration**，即使只有一个 Participant（自己）。

```xml
<definitions>
  <collaboration id="collab1">
    <participant id="self" name="Self" processRef="process1" />
    <participant id="other" name="External" />
    <messageFlow sourceRef="self" targetRef="other" messageRef="msg1" />
  </collaboration>

  <process id="process1">
    <sendTask id="send1" messageRef="msg1" />
  </process>

  <message id="msg1" name="Order" />
</definitions>
```

## 10.6 引擎实现要点

### 10.6.1 引擎对 Collaboration 的支持程度

| 能力                        | 必需性 | 说明                                 |
| --------------------------- | ------ | ------------------------------------ |
| 解析 Collaboration 元素     | ✅     | 至少能识别 Participant               |
| 关联 Process 与 Participant | ✅     | 通过 processRef                      |
| 处理 MessageFlow            | ✅     | 用于 Send/Receive Task 的对端识别    |
| 渲染 Pool/Lane              | ❌     | 引擎不渲染图形                       |
| 执行 Choreography           | ❌     | Process Execution Conformance 不要求 |
| 多 Pool 实例协调            | ⚠️     | 取决于引擎设计                       |

### 10.6.2 引擎内部模型

```java
interface Collaboration {
    List<Participant> getParticipants();
    List<MessageFlow> getMessageFlows();
    boolean isClosed();
}

interface Participant {
    String getName();
    Optional<Process> getProcessRef();  // 黑盒 Pool 没有内部 Process
    List<Interface> getInterfaces();
}

interface MessageFlow {
    InteractionNode getSource();  // Pool, Activity, or Event
    InteractionNode getTarget();
    Optional<Message> getMessage();
}
```

### 10.6.3 跨 Pool 消息的执行

引擎通常**不直接执行 Collaboration**，而是：

1. 每个 Pool 内的 Process 独立执行
2. Send Task / Send Event → 通过 Message Flow 找到目标 Participant → 投递消息
3. Receive Task / Catch Event → 通过 Message Flow 知道期望什么消息

### 10.6.4 多 Pool 协调的两种模式

**模式 1：单一引擎内部**

- 所有 Pool 的 Process 都在同一引擎内执行
- 引擎内部消息总线（Event Bus）传递消息

**模式 2：跨引擎外部**

- 不同 Pool 在不同引擎（甚至不同组织）
- 通过外部消息系统（MQ、HTTP、Web Service）通信
- **依赖 Correlation 机制**匹配流程实例

### 10.6.5 实践建议

✅ **建议**：

1. **简化 Pool 设计**：大多数业务流程用 2 个 Pool 就够了（"自己" + "外部"）
2. **Black Box 处理**：对端 Pool 用黑盒表示，专注自己的 Process
3. **Message Flow + Message + Correlation** 是引擎支持的最低组合
4. **不要执行 Choreography**：Choreography 是建模工具的概念，引擎不应直接执行
